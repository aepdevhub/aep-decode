AEP Schemas

Schemas are one of the core concepts in Adobe Experience Platform. An AEP schema defines the structure and meaning of the data that is ingested into the platform.

Schemas help AEP understand what each field represents, what type of data it contains, and how that data can be used across datasets, identity and Real-Time Customer Profile.

1. What is an AEP Schema?

An AEP schema is a blueprint that describes the structure of data stored in Adobe Experience Platform.

Example Customer Data:

Customer ID → CUST10001
First Name → Rahul
Last Name → Kumar
Email → rahul@example.com
Mobile → 9876543210

The schema defines fields such as Customer ID, First Name, Email and Mobile, along with their data types and other properties.

2. XDM - Experience Data Model

AEP uses the Experience Data Model (XDM) to standardize the structure of data across different systems and applications.

Business Data ↓ XDM Schema ↓ Dataset ↓ Data Lake / Profile ↓ Analytics / Segmentation / Activation

XDM provides a common language for describing customer and business data.

3. Why Do We Need Schemas?

  • Define the structure of incoming data
  • Standardize data across different systems
  • Define field names and data types
  • Support identity configuration
  • Support Real-Time Customer Profile
  • Make data easier to understand and use
  • Help different applications work with consistent data

4. Main Types of Data in AEP

AEP commonly works with data describing customer entities and customer interactions.

Data Type Purpose Example
Profile Data Describes a customer or entity Name, Email, Customer ID
Experience Event Data Describes an interaction or event Product View, Add to Cart, Purchase

5. Individual Profile Schema

An Individual Profile schema is used to represent information about an individual customer or person.

Example:

Customer ID → CUST10001
First Name → Rahul
Last Name → Kumar
Email → rahul@example.com
Phone → 9876543210

This type of information can describe the customer itself rather than a particular interaction.

6. Experience Event Schema

An Experience Event schema represents an interaction or activity performed by a customer or another entity.

Example Customer Events:

Product Viewed
↓
Product Added to Cart
↓
Checkout Started
↓
Purchase Completed

Each event can contain information such as the event time, product, customer identity and other relevant attributes.

7. Schema Components

An XDM schema is built using several important components.

Component Purpose
Class Defines the basic structure and behavior of the schema
Field Group Provides reusable groups of related fields
Data Type Defines the type and structure of a field
Attributes / Fields Store individual pieces of information
Identity Allows a field to participate in identity handling

8. Class

A class determines the base structure of an XDM schema and indicates the type of data the schema represents.

Think of a Class as:

The foundation or starting point of an XDM schema.

The class is selected when creating a schema and provides the basic structure on which field groups and fields are added.

9. Field Groups

Field groups are reusable collections of related fields that can be added to a schema.

Example:

Personal Details
→ First Name
→ Last Name
→ Email
→ Phone

Using field groups allows commonly used fields to be reused across different schemas.

10. Attributes / Fields

Fields represent individual pieces of information within a schema. Each field has a data type and can have additional configuration.

Field Example Value Type
customerId CUST10001 String
firstName Rahul String
age 35 Integer
email rahul@example.com String

11. Data Types

A field's data type defines what kind of value can be stored in that field.

Data Type Example
String Rahul
Integer 35
Boolean true / false
Date 2026-09-19
Date-Time 2026-09-19T10:30:00Z
Array Multiple values

12. Required Fields

A field can be configured as required when the business data model requires that field to be present.

Example:

Customer ID → Required
Email → Optional

The required configuration should be used carefully because incoming data must satisfy the schema requirements.

13. Identity Field in a Schema

A field in an XDM schema can be configured as an identity when the field represents an identifier that should participate in identity handling.

Example:

Field → customerId
Type → String
Identity → Enabled
Namespace → Customer ID
Customer ID ↓ Identity Namespace ↓ Identity Graph ↓ Customer Profile

14. Primary Identity

A schema can have a primary identity used to identify the entity represented by the record.

Example:

Field → customerId
Namespace → Customer ID
Primary Identity → Yes

15. Enum

An enum can be used when a field should accept values from a defined set of options.

Example: Customer Type

Individual
Business
Partner

Using defined values helps maintain consistency in the data.

16. Profile Schema vs Experience Event Schema

Profile Schema Experience Event Schema
Describes a customer or entity Describes an interaction or event
Name, Email, Phone Product View, Purchase, Login
Customer information Event information
Used to represent the entity Used to represent activity

17. Schema and Dataset

A schema defines the structure of the data, while a dataset is where the data is stored.

Schema ↓ Defines Data Structure Dataset ↓ Stores Data
Example:

Customer Schema
→ customerId
→ firstName
→ lastName
→ email

Customer Dataset
→ Stores records that follow this schema

18. Schema and Identity

Identity configuration in the schema allows appropriate fields to participate in identity handling.

Schema ↓ Identity Field ↓ Identity Namespace ↓ Dataset ↓ Identity Graph ↓ Profile

22. Developer View

As an AEP developer, it is important to understand how data moves from source systems into XDM schemas, datasets and ultimately customer profiles.

Source System ↓ Data Mapping ↓ XDM Schema ↓ Dataset ↓ Ingestion ↓ Identity Resolution ↓ Real-Time Customer Profile

23. Common Schema Design Considerations

  • Understand the business requirement before creating the schema
  • Select the appropriate class
  • Use appropriate field groups
  • Define meaningful attributes
  • Select correct data types
  • Configure identity fields carefully
  • Use enums where a controlled set of values is required
  • Avoid creating unnecessary duplicate fields
  • Design the schema according to the intended dataset and use case

26. Interview Questions

What is an AEP schema?

An AEP schema defines the structure, fields and data types used to represent data in Adobe Experience Platform.

What is XDM?

XDM stands for Experience Data Model. It provides a standardized way to structure data in Adobe Experience Platform.

What is a field group?

A field group is a reusable collection of related fields that can be added to an XDM schema.

What is the difference between a schema and a dataset?

A schema defines the structure of the data, while a dataset stores data that follows that structure.

What is an Experience Event?

An Experience Event represents an interaction or activity associated with a person or entity at a particular point in time.

Why is identity configured in a schema?

Identity configuration allows appropriate fields to participate in identity handling and identity resolution.
